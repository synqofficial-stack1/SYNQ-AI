# Synq Android / Google Play release gate

Updated 2026-10-22. Synq now targets Android and Google Play first. The iOS settings in `app.json` (bundle ID, Sign in with Apple) are left in place but dormant: nothing iOS-specific runs on Android, and the Apple button never renders there.

A row is **DONE** only with evidence from this repository or the live Supabase project. Store listing copy and Data safety answers are in `docs/play-store-listing.md`.

## Owner steps, in order

1. ~~Approve the account-deletion and search-path migrations and the `delete-account` deploy.~~ Done 2026-10-22.
2. Fill `src/constants/legal.ts` and have the privacy text reviewed.
3. Sign in to Expo and link the project (adds `extra.eas.projectId` to `app.json`):

   ```bash
   npx eas-cli login
   npx eas-cli init
   ```

4. `.env.local` is never uploaded to EAS, so give the builds their public Supabase values (enter the values when prompted; repeat with `--environment production`):

   ```bash
   npx eas-cli env:create --environment preview --name EXPO_PUBLIC_SUPABASE_URL --visibility plaintext
   npx eas-cli env:create --environment preview --name EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY --visibility plaintext
   ```

5. Host the web app and note its URL (`npx expo export --platform web`, then `npx eas-cli deploy --prod`). Add that URL to Supabase Redirect URLs and to the `SOCIAL_ALLOWED_ORIGINS` secret.
6. Build a test APK, install it on an Android phone, and try sign-up, email and Google sign-in, onboarding, chat, the CRM, and deleting a throwaway account:

   ```bash
   npx eas-cli build --platform android --profile preview
   ```

7. Create a Google Play developer account, create the app (package `com.synq.ai`), and complete Policy → App content from `docs/play-store-listing.md`.
8. Build the release bundle and upload the first one by hand to Internal testing in Play Console:

   ```bash
   npx eas-cli build --platform android --profile production
   ```

   Later builds can go up with `npx eas-cli submit --platform android --profile production` after adding a Google service-account key in EAS.
9. Personal developer accounts: run a closed test with at least 12 testers for 14 days, then apply for production.
